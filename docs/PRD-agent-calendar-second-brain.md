# PRD: Agent Calendar, 나를 이해하고 일하는 AI 캘린더

- Status: Authoritative product direction
- Date: 2026-08-02
- Reframes: `docs/PRD-agent-calendar-agent-platform-additions.md`

## 1. Summary

Agent Calendar는 AI를 자주 쓰는 1인 운영자를 이해하고 기억하며 필요한 일을 실제로
수행할 수 있는 캘린더 서비스다. 현재 캘린더 중심 UI와 정보구조를 유지하면서 사용자가
허용한 파일, 일정, 메일, 메모 같은 원본을 읽어 사람, 프로젝트, 목표, 관심사, 진행 중인
일을 파악한다.

사용자는 기존 캘린더 화면에서 중요한 일정과 일을 파악하고 Calendar AI와 자연스럽게
대화한다. 필요한 일은 기존 에이전트 화면의 `작업`으로 이어지고, 수행 결과와 근거는
다시 캘린더와 Wiki에 보고된다. Second Brain과 LLM Wiki는 이 경험을 가능하게 하는
기억 계층이며 캘린더를 대체하는 별도 제품이 아니다.

## 2. Contacts

| 역할 | 담당 | 책임 |
| --- | --- | --- |
| 제품 책임자 | 사용자 | 고객, 핵심 약속, 출시 우선순위 결정 |
| 제품 설계·구현 | Codex | 명세, 구현 계획, 검증, 실제 표면 증거 |
| 데이터 소유자 | 각 Workspace 소유자 | 연결 원본, 접근 범위, 기억과 자동화 승인 |

## 3. Background

첫 고객은 여러 프로젝트를 동시에 운영하며 AI를 이미 자주 사용하는 1인 사업가,
창업자, 프리랜서, 크리에이터다. 이들은 개발자가 아니어도 다음 문제를 반복해서
겪는다.

- 일정, 메일, 메모, 녹음, 파일과 AI 대화가 서로 흩어져 있다.
- AI를 새로 열 때마다 자신과 프로젝트의 배경을 다시 설명한다.
- AI가 만든 결과가 대화창에 묻히고 다음 일과 연결되지 않는다.
- 해야 할 일, 후속 연락, 반복 업무를 사람이 계속 기억하고 챙긴다.
- AI에게 일을 시켜도 진행, 중단, 수정, 결과 보관을 한곳에서 관리하기 어렵다.

기존 Agent Calendar 기획은 캘린더, Agent Work, Runner, provider session, Wiki 검색을
각각 구현했다. 그러나 첫 로그인에서 사용자를 이해해 주는 경험과 모든 기능을 잇는
하나의 기억·실행 루프가 없었다. 화면에 에이전트 기능이 있어도 실제 사용자의 맥락을
자동으로 조립하지 못했고, Calendar AI와 Wiki도 서로 분리된 도구처럼 동작했다.

이 PRD는 캘린더 중심 제품의 정체성을 유지하면서 `일정만 표시하는 캘린더`를
`사용자를 이해하고, 기억하고, 실제 일을 수행한 뒤 다시 보고하는 캘린더`로
업그레이드한다. Second Brain, Wiki, Agent Work, Automation은 이 캘린더 경험을 강화하는
하위 능력이다.

## 4. Objective

사용자가 처음부터 긴 설정이나 반복 설명을 하지 않아도 캘린더가 허용된 원본을
바탕으로 사용자를 파악하고, 현재 중요한 일정과 일을 알려주며, 필요한 작업을 실행하고,
결과를 다시 캘린더와 기억에 반영하게 한다.

핵심 고객 과업은 다음과 같다.

> 내 캘린더가 나와 내 일을 이미 알고 있어서, 지금 중요한 것을 알려주고 필요한 일은
> 직접 처리한 뒤 결과까지 다음 일정과 판단에 반영해 주면 좋겠다.

### Key Results

초기 개인 베타에서 다음 목표를 검증한다.

- 신규 사용자의 80% 이상이 첫 세션에서 원본 소스 하나 이상을 연결하고 세컨드 브레인
  초안을 확인한다.
- 연결 가능한 원본이 있는 사용자의 80% 이상이 10분 안에 근거가 표시된 첫 사용자 이해
  결과를 받는다.
- 사용자 이해 결과에 표시된 사실의 95% 이상이 원본 출처를 가진다. 근거 없는 성격,
  목표, 관계 추정은 0건이어야 한다.
- 신규 사용자의 70% 이상이 첫 세션에서 Calendar AI 질문 또는 실제 작업 하나를
  완료한다.
- 완료된 작업의 100%가 Work Conversation, 결과, 사용한 맥락, Wiki 기록 또는 명시적인
  저장 제외 결정을 남긴다.
- 외부 전송, 구매, 삭제, 새 권한 사용이 사용자 승인 없이 실행되는 경우를 0건으로
  유지한다.
- 앱 재시작 뒤 세컨드 브레인, 작업 대화, 장기 기억, 자동화 상태 복구 성공률을 100%로
  유지한다.

## 5. Market Segments

### 첫 고객: AI를 쓰는 1인 운영자

인구 통계가 아니라 다음 상황과 문제로 정의한다.

- 한 사람이 여러 고객, 프로젝트, 콘텐츠, 운영 업무를 동시에 맡는다.
- Google Calendar, Gmail, 문서, 메모, 녹음, ChatGPT, Claude 등을 이미 사용한다.
- 전담 비서나 운영팀은 없지만 정보와 후속 작업은 계속 늘어난다.
- 코드를 다루지 않더라도 AI가 조사, 정리, 문서 작성, 비교, 계획, 보고를 대신하길
  원한다.
- 복잡한 모델, Runner, 세션 설정보다 결과와 신뢰를 중요하게 생각한다.

### 후속 고객

- 소규모 팀의 대표와 운영 책임자
- 컨설턴트, PM, 세일즈, 리서처 같은 지식 노동자
- 개인 기록과 일정, 창작 활동을 한곳에서 관리하려는 크리에이터

### 제약

- 첫 출시는 한 사람의 Workspace에 집중한다.
- 코딩 프로젝트 폴더를 지원하지만 코딩을 기본 전제로 두지 않는다.
- 모든 원본을 클라우드 또는 로컬 중 어디에 보관할지는 별도 결정으로 남긴다.
- macOS 전체 디스크를 동의 없이 탐색하지 않는다.

## 6. Value Propositions

### 처음부터 나를 이해하는 AI

빈 대화창 대신 허용된 실제 원본을 분석한 세컨드 브레인 초안으로 시작한다. 사용자는
자신, 중요한 사람, 프로젝트, 목표와 진행 중인 일을 매번 다시 설명하지 않는다.

### 기록이 사라지지 않는 LLM Wiki

파일, 메일, 일정, 녹음, 글, 작업 대화와 결과의 원본을 보관한다. AI가 이를 사람,
프로젝트, 결정, 아이디어, 할 일, 반복 패턴으로 연결하며 모든 기억은 원본 출처를
가진다.

### 대화에서 실제 일로 이어지는 Calendar AI

사용자는 Calendar AI에 자연스럽게 말한다. “이거 조사해줘”, “다음 주에 해줘”,
“정리해서 남겨줘”라는 요청은 같은 맥락을 가진 작업, 일정 또는 Wiki 기록으로
전환된다.

### 사람 대신 일하고 보고하는 에이전트

에이전트는 Codex나 Claude 서비스처럼 작업별 대화를 유지하고 실제 도구를 사용한다.
사용자는 진행 상황을 보고, 중단하고, 추가 지시하고, 결과를 수정할 수 있다. 완료된
결과는 근거와 함께 보고되고 세컨드 브레인에 다시 쌓인다.

### 반복될수록 줄어드는 운영 부담

반복되는 일정과 작업 패턴을 발견해 자동화 루틴을 제안한다. 사용자가 승인한 루틴은
정해진 조건에 따라 실행하고 결과를 보고한다.

## 7. Solution

### 7.1 UX and primary flow

#### UI 진화 원칙

- 현재 Desktop의 navigation, 화면 배치, interaction pattern, design token을 기준선으로
  유지한다.
- `캘린더`는 기본 진입점이자 일정, AI 작업, 자동화와 보고가 다시 모이는 중심 화면이다.
- `오늘`, `다음 7일`, `메일함`, `에이전트`, `자동화`, `위키`, `일기`, `주간 회고`는
  현재 위치에서 필요한 기능만 추가한다.
- Second Brain은 별도 상시 대시보드가 아니라 첫 설정 결과, Calendar AI의 근거, Wiki의
  연결 정보처럼 필요한 순간에만 드러나는 기반 능력이다.
- 새 top-level 화면, 대체 홈, 별도 AI 작업실 navigation은 기존 화면으로 해결할 수 없다는
  검증 전에는 만들지 않는다.
- 새 UI는 기존 component와 token을 재사용하며 기존 기능과 버튼의 위치·의미를 이유 없이
  바꾸지 않는다.

#### 첫 로그인과 사용자 이해

첫 로그인 후에도 기존 Desktop shell과 navigation을 유지한다. 기존 `시작 가이드` 영역을
원본 연결과 사용자 이해 진행·검토에 맞게 업그레이드하고, 실제 접근 권한을 받은 원본이
있을 때 분석을 시작한다.

```text
로그인
  → 기존 시작 가이드에서 원본 연결 또는 분석 범위 허용
  → “Agent Calendar가 사용자를 파악 중입니다”
  → 원본 인덱싱과 사용자 이해 생성
  → 나의 세컨드 브레인 초안 검토
  → 기존 Calendar AI + Wiki + 에이전트/자동화 화면에 맥락 적용
  → 캘린더 화면
```

진행 화면은 가짜 퍼센트를 사용하지 않는다. 다음과 같은 실제 단계를 표시한다.

- 연결한 원본 확인
- 파일과 기록 읽기
- 사람과 프로젝트 연결
- 목표, 관심사, 진행 중인 일 정리
- 세컨드 브레인 초안 만들기

분석 결과 화면은 다음을 보여준다.

- 나에 대해 파악한 사실과 선호
- 중요한 사람과 관계
- 현재 프로젝트와 목표
- 진행 중인 일과 놓친 후속 조치
- 자주 반복되는 일정과 행동
- 아직 알 수 없거나 확인이 필요한 항목
- 각 판단의 원본 출처

사용자는 결과를 확인, 수정, 제외할 수 있다. 수정은 새 사용자 이해 버전으로 저장되고
이전 버전과 출처를 잃지 않는다.

#### 자동으로 만들어지는 첫 상태

검토된 세컨드 브레인 초안으로 다음을 만든다.

- Calendar AI가 사용할 사용자·프로젝트·일정 맥락
- 사람, 프로젝트, 목표, 결정, 기록을 연결한 LLM Wiki 첫 구조
- 사용자 업무에 맞는 담당 에이전트 초안
- 에이전트별 책임, 허용 맥락, 장기 기억 초안
- 반복 패턴을 바탕으로 한 자동화 루틴 제안
- 오늘 중요한 일정, 열린 일, 첫 추천 행동을 담은 브리핑

에이전트와 자동화는 초안을 자동 생성할 수 있지만 외부 행동이나 반복 실행은 사용자
검토와 활성화 전까지 시작하지 않는다.

#### 일상 사용 루프

```text
캘린더에서 파악 → 이해 → 계획 → 작업 → 보고
       ↑                              ↓
       └──── 기억하고 다음 캘린더에 반영 ────┘
```

- 기록: 텍스트, 음성, 파일, 메일, 일정, 작업 결과를 받는다.
- 이해: 사람, 프로젝트, 결정, 목표, 할 일, 반복 패턴을 연결한다.
- 계획: 캘린더와 Calendar AI가 지금 중요한 일과 다음 행동을 제안한다.
- 작업: 기존 에이전트 화면에서 에이전트가 실제 일을 수행한다.
- 보고: 결과, 근거, 변경 사항, 남은 제약을 캘린더와 작업 대화에 보여준다.
- 기억: 원본과 구조화된 기억을 다음 대화와 작업에 사용한다.

#### 주요 화면

- `캘린더`: 현재 일정, 중요한 일, AI 작업과 자동화 상태, 완료 보고가 모이는 기본 화면
- `오늘`·`다음 7일`: 기존 일정 보기에 사용자 맥락 기반 브리핑과 우선순위를 보강
- `메일함`: 기존 메일 연결과 목록에서 일정·작업·기억으로 이어지는 행동을 보강
- `에이전트`: 기존 화면을 지속형 작업 대화, 진행, 중단, 전체 결과가 동작하도록 업그레이드
- `자동화`: 기존 화면에서 반복 패턴 제안, 승인, 실행과 보고를 연결
- `위키`·`일기`·`주간 회고`: 기존 기록 경험에 원본 출처, 관계, 기억 환류를 보강
- `기본함`·`칸반 보드`·`위젯`·`Runner 설정`: 현재 역할과 위치를 유지하고 필요한 연결만 추가

`Runner`, `provider session`, `endpoint`, `canonical transcript`, 모델 ID는 기본 화면에
노출하지 않는다. 필요한 경우에만 고급 설정과 진단 화면에서 보여준다.

### 7.2 Key features

#### P0: 첫 가치 경험

1. **사용자를 이해하는 통합 캘린더**
   - 기존 캘린더 UI, 일정 생성·수정, 외부 캘린더 표시를 유지한다.
   - 일정 옆에 관련 프로젝트, 열린 일, 진행 중인 에이전트 작업과 완료 보고를 연결한다.
   - 사용자가 지금 알아야 할 변화와 다음 행동을 설명하되 기존 일정 조작을 방해하지 않는다.

2. **원본 수집과 자동 보관**
   - 사용자 동의를 받은 파일, 일정, 메일, 메모, 녹음, 글을 원본 단위로 보관한다.
   - 원본은 생성 시각, 출처, 접근 권한, 변경 시각을 가진다.
   - 저장 위치가 로컬인지 클라우드인지는 출처별 정책으로 결정하며 별도 제품 결정을
     따른다.

3. **사용자 이해와 세컨드 브레인 초안**
   - 사람, 프로젝트, 목표, 관심사, 선호, 진행 중인 일, 열린 질문, 반복 패턴을 추출한다.
   - 모든 사실과 관계는 하나 이상의 원본 출처 또는 사용자 직접 확인을 가진다.
   - 불확실한 내용은 사실로 저장하지 않고 질문 또는 제안으로 표시한다.

4. **Calendar AI**
   - 일정만이 아니라 사용자가 허용한 Wiki, 작업, 메일과 기록을 함께 이해한다.
   - 대화에서 일정, 작업, 기록 생성을 제안하거나 실행한다.
   - 쓰기와 외부 행동은 정책에 따라 미리보기와 승인을 제공한다.

5. **LLM Wiki**
   - 원본 기록과 구조화된 지식을 분리한다.
   - 사람, 프로젝트, 목표, 결정, 아이디어, 일정, 작업, 결과를 연결한다.
   - 자연어 질문, 출처 확인, 수정, 삭제, 기억 제외를 지원한다.

6. **기존 에이전트 화면의 작업 경험**
   - 폴더 없는 일반 업무와 특정 로컬 프로젝트 폴더 작업을 모두 지원한다.
   - 작업별 대화, 맥락, 진행, 결과, 산출물과 개입을 저장한다.
   - 사용자는 실행 중 추가 지시, 중단, 재시도, 수정을 할 수 있다.
   - 긴 최종 답변을 임의로 자르지 않고 사용자에게 그대로 보여준다.
   - 여러 작업은 각자 독립 상태를 가지며 Runner 역량 범위에서 병렬 실행한다.

7. **Context Assembler**
   - 현재 대화, 세컨드 브레인, 관련 Wiki, 일정, 메일, 이전 작업, 에이전트 기억,
     선택한 폴더를 작업별로 조립한다.
   - 어떤 맥락을 왜 선택했는지 기록하고 사용자가 제외할 수 있게 한다.
   - 모든 내용을 무제한으로 넣지 않고 관련성, 권한, 최신성, 예산에 따라 제한한다.

8. **결과 보고와 기억 환류**
   - 에이전트는 수행한 일, 결과, 근거, 만든 산출물, 실패, 다음 제안을 보고한다.
   - 완료 결과는 Wiki와 작업 대화에 저장하고 필요하면 캘린더 후속 일정으로 만든다.
   - 사용자의 수정과 유용성 평가는 다음 작업 맥락에 반영한다.

#### P1: 지속적으로 일하는 에이전트

9. **에이전트 프로필과 장기 기억**
   - 역할, 책임, 지침, 말투, 전문 분야, 허용 정보, 도구, 보고 방식을 가진다.
   - 에이전트 기억은 출처, 생성 이유, 수정·삭제 이력을 가진다.
   - 기존 Codex, Claude, Hermes 에이전트를 가져올 때 이름만 등록하지 않고 실제 실행
     지침 또는 provider-native agent 선택이 적용돼야 한다.

10. **자동화 루틴**
   - 반복 일정, 반복 작업, 사용자의 수정 패턴을 바탕으로 루틴을 제안한다.
   - 조건, 주기, 사용할 에이전트, 맥락, 결과 위치, 승인 정책을 보여준다.
   - 사용자가 활성화하기 전에는 반복 실행하지 않는다.
   - 실행마다 결과를 보고하고 실패 시 조용히 넘어가지 않는다.

#### P2: 확장

- 외부 메시징 채널
- 여러 사람의 공유 Workspace
- 에이전트 협업과 하위 작업
- 여러 실행 엔진 결과 비교
- Mobile

### 7.3 Technology contracts

- `Source Record`는 원본의 출처, 소유권, 시간, 접근 정책, 무결성 식별자를 가진다.
- `Second Brain Snapshot`은 추출된 사실과 관계, 출처, 신뢰도, 사용자 확인 상태,
  생성 버전을 가진다.
- `Context Envelope`은 한 Calendar AI 응답 또는 작업 실행에 실제 사용한 원본·기억·
  도구·권한을 기록한다.
- 원본 기록, 구조화된 Wiki 지식, 사용자 확인 기억, 에이전트 기억, provider-native
  session history를 같은 데이터로 취급하지 않는다.
- Calendar AI와 모든 에이전트는 공통 Context Assembler를 사용하되 자신의 권한과
  목적에 맞는 범위만 받는다.
- 일반 작업은 Runner를 시작한 우연한 현재 디렉터리에 의존하지 않는다. 폴더 작업은
  명시적으로 저장된 작업 위치를 사용하고, 폴더 없는 작업은 Workspace 맥락으로
  실행한다.
- 완료된 작업의 최종 답변은 저장과 표시 과정에서 의미가 바뀌거나 임의로 잘리지
  않아야 한다.
- 실제 분석이 시작되기 전에는 “사용자를 파악 중”이라고 표시하지 않는다. 진행 상태는
  실제 source ingest와 index checkpoint에서만 나온다.
- 외부 전송, 게시, 구매, 삭제, 새 권한은 기존 Approval Gate를 통과한다.
- provider credential과 로컬 비밀정보는 사용자 Runner 밖으로 보내지 않는다.

### 7.4 Assumptions to validate

- 사용자는 명확한 가치와 접근 범위를 보면 파일, 캘린더, 메일 연결을 허용한다.
- 빈 화면보다 출처가 있는 세컨드 브레인 초안이 첫 사용 가치를 빠르게 만든다.
- 자동 추출된 사용자 이해에는 오류가 있으므로 쉬운 수정·제외 경험이 신뢰에 중요하다.
- 사용자는 에이전트 이름이나 모델보다 “무슨 일을 대신하고 어떻게 보고하는가”를 더
  중요하게 생각한다.
- 자동화는 자동 생성보다 검토 가능한 제안과 첫 성공 실행이 신뢰를 높인다.
- 원본 저장 위치와 기기 간 동기화 정책은 사용자 신뢰와 성능에 큰 영향을 주므로 별도
  검증이 필요하다.

## 8. Release

### Release A: 캘린더가 나를 이해하기 시작

- 기존 시작 가이드 안의 사용자 이해 진행·검토
- 최소 한 종류의 실제 파일 원본과 Google Calendar/Gmail 연결
- 원본 자동 보관과 출처가 있는 사용자 이해 초안
- 기존 캘린더, Calendar AI와 Wiki에 첫 맥락 적용
- 수정, 제외, 다시 분석

완료 조건:

- 실제 빈 계정과 실제 자료가 있는 계정 모두 막힘 없이 온보딩한다.
- 자료가 있는 사용자는 출처가 있는 사람, 프로젝트, 목표, 열린 일의 초안을 받는다.
- 자료가 없으면 내용을 만들어내지 않고 연결할 원본을 안내한다.
- 기존 navigation과 주요 화면의 기능·시각 구조가 유지된다.

### Release B: 대화에서 작업과 보고까지

- Calendar AI 대화를 같은 맥락의 작업으로 전환
- 기존 에이전트 화면의 비개발자용 작업 경험
- 실제 에이전트 실행, 실시간 진행, 중단, 추가 지시, 재시도
- 결과·산출물의 Wiki 환류와 캘린더 후속 조치

완료 조건:

- 사용자가 배경을 다시 설명하지 않고 Calendar AI 대화를 작업으로 이어간다.
- 작업 결과가 임의로 잘리지 않고 근거, 산출물과 함께 복구된다.
- 폴더 없는 일반 작업과 폴더가 있는 작업이 모두 실제로 완료된다.

### Release C: 지속형 에이전트와 루틴

- 사용자에 맞는 에이전트 초안과 활성화
- 출처가 있는 에이전트 장기 기억
- 반복 패턴 기반 자동화 루틴 제안
- 승인된 루틴 실행과 보고

완료 조건:

- 서로 다른 에이전트가 실제 프로필과 기억에 맞게 행동한다.
- 승인된 루틴이 정해진 맥락으로 실행되고 결과를 Wiki와 Calendar에 남긴다.
- 실패, 권한 부족, Runner 오프라인을 숨기지 않고 사용자가 해결할 수 있게 한다.

### Release D: 확장 채널과 협업

- 외부 채널
- 여러 사용자 Workspace
- Mobile
- 고급 에이전트 협업과 엔진 비교

### Explicitly deferred

- 동의 없는 전체 디스크 스캔
- 확인되지 않은 사실의 자동 장기 기억 확정
- 사용자 승인 없는 외부 행동과 자동화 활성화
- provider 공식 앱과의 완전한 양방향 대화 동기화
- 첫 출시의 조직용 관리 기능
